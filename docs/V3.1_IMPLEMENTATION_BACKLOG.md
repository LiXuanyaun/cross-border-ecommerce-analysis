## 1. 北极星目标

让运营人员可以在一次连续流程中完成：

```text
导入业务数据
→ 确认字段映射与数据质量
→ 生成稳定分析范围
→ 发现重点异常或机会
→ 核查规则、指标和证据
→ 创建处理任务
→ 导出同口径报告
→ 下周期复盘结果
```

v3.1 不以新增分析页面为目标，而以可靠性、性能和功能闭环为目标。

## 2. 强制开发顺序

```text
数据契约与导入
→ 指标和规则唯一来源
→ 证据链与 scope_id
→ 页面真实消费
→ 任务与报告闭环
→ AI 受控表达
```

任何绕过正式指标、规则、证据和 `scope_id` 的页面逻辑，都应视为 v3.1 技术债。

## 3. P0 Backlog：试点前必须完成

### P0-1 Web 数据导入闭环

交付：

- CSV / XLSX 上传。
- Excel Sheet 选择。
- 多文件选择和同构合并。
- 编码识别，覆盖 UTF-8、UTF-8 BOM 和常见中文编码。
- 字段自动推荐映射，低可信映射必须人工确认。
- 订单粒度、订单商品粒度和金额语义确认。
- 单币种与多币种确认。
- 质量预检、阻断问题、警告问题和能力影响说明。
- `dataset_id`、`source_file_id`、原始行号和导入状态。

验收：

- S01、S08、S09、S10、S17、S19、S20 自动化通过。
- 多文件导入失败时无部分业务记录入库。
- 相同文件重复导入不重复写入订单。
- DataHub 不再展示静态导入记录、硬编码质量分或禁用入口。

### P0-2 数据契约升级

交付：

- 同时支持订单粒度和订单商品粒度。
- 统一唯一键策略。
- 统一金额语义，禁止订单总金额在商品行中重复求和。
- 保留原始金额、原币种、汇率日期、汇率来源和换算金额。
- 生成能力矩阵，缺字段时停用对应分析。
- 引入稳定 `scope_id`，用于页面、报告、导出、任务和 AI。

验收：

- 订单数始终按订单唯一键去重。
- 订单商品明细不会被当作订单数。
- 汇率覆盖不足时停止跨币种金额结论。
- 缺利润、退货、客户字段时只停用对应模块，不影响可用模块。

### P0-3 指标、规则、诊断和建议统一

交付：

- Overview、Topic Analysis、Report Preview、Excel、DOCX、AI 栏和 Task Drawer 使用同一分析链路。
- 删除或收敛 Runtime Topic 内临时异常、动作和比较逻辑。
- 每条正式结论绑定 `metric_id`、`rule_id`、`rule_version`、`metric_version` 和 `evidence_id`。
- 规则详情可从页面与报告查看。

验收：

- 页面、报告、导出和任务数字一致。
- Topic Analysis 不维护第二套判断口径。
- 数据不足时不生成确定性原因或建议。

### P0-4 场景矩阵自动化

交付：

- 建立 S01-S20 可重复数据集。
- 导入、字段、粒度、金额、币种、周期、规则、抑制和恢复测试。
- React 四个主页面桌面和 393px 浏览器回归。
- 100,000 行性能场景进入本地门禁。

验收：

- 20 个场景全部自动覆盖。
- 所有核心指标覆盖正常值、零分母、缺字段和边界周期。
- 关键 E2E 不允许跳过后仍视为通过。

### P0-5 第一轮性能治理

交付：

- 分解 100,000 行完整流水线耗时。
- 避免每个分析范围全量生成和写入无用派生对象。
- Topic Analysis 查询按需计算或缓存。
- 明细搜索和分页走数据库分页。
- 报告复用当前分析结果。
- 增加 scope 保留、清理、归档和容量查看。

验收：

- 100,000 行完整分析不超过 15 秒。
- 34,500 行专题冷启动不超过 5 秒。
- 常用筛选 P95 不超过 3 秒。
- 明细搜索和分页 P95 不超过 500 ms。
- 100,000 行报告生成不超过 30 秒。

## 4. P1 Backlog：长期使用必须完成

### P1-1 Overview 产品化补齐

- KPI、Mini Trend、经营趋势、待办、市场、商品、增长机会和经营洞察全部使用正式分析结果。
- 所有卡片提供周期、阈值、公式或规则入口。
- 洞察不得重复待处理事项。
- 所有 Drawer 和详情入口真实可用。

### P1-2 Topic Analysis 产品化补齐

- 五主题拥有独立 KPI、趋势、排行、明细和导出。
- 日期、市场、品类筛选同步 URL，并进入 `scope_id`。
- 明细搜索、分页、每页数量、查看详情和导出完整可用。
- 右侧 AI 栏只解释当前结构化结果，不生成页面外结论。

### P1-3 任务闭环

- 异常、机会和洞察都可创建任务。
- 任务包含 owner、deadline、status、result_note、review_result。
- 任务支持待处理、处理中、已完成、已复盘和关闭。
- 关闭任务必须记录关闭原因、关闭人和关闭时间。
- 复盘只记录结果，不改写原始异常事实。

### P1-4 报告与导出补齐

- Report Preview 继承当前筛选和 `scope_id`。
- Excel 多 Sheet 导出。
- DOCX 报告导出。
- 报告包含数据质量、规则详情和证据链。
- 页面、预览和导出数字一致。

## 5. P2 Backlog：Agent 与工程治理

### P2-1 Agent 可靠性

- AI 输出绑定 `rule_id` 和 `evidence_id`。
- AI 状态覆盖 `SUCCESS`、`PARTIAL`、`SKIPPED`、`FAILED`、`FATAL`。
- 支持当前会话内追问。
- 会话恢复、证据一致性和状态可靠性完成。
- 暂不开发自主规划、多工具循环、长期记忆或自动执行。

### P2-2 技术债治理

- 拆分 `crossborder_api/runtime.py`。
- 拆分大型前端页面。
- 增加 FastAPI response model 和 OpenAPI 类型同步。
- 路由级前端按需加载，首屏 JS 压缩前控制在 900KB 以内或完成代码分割。
- 增加 CI、性能门禁、Docker smoke test 和结构化日志。

### P2-3 试点准备

- 准备 3-5 名真实运营人员的 4 周试点流程。
- 记录导入成功率、复盘耗时、任务接受率、复盘回访率和结论可信度。
- 用真实任务结果校准规则阈值和建议边界。

## 6. 不进入 v3.1

- 店铺 API 自动同步。
- 实时数据。
- 云部署。
- 多租户和复杂权限。
- 移动端原生 App。
- 自动执行型 Agent。
- 广告平台、库存、价格或店铺配置自动操作。
- 预测模型。
- 长期记忆系统。
- 多 Agent 协作。

## 7. v3.1 完成定义

v3.1 只有在以下条件全部满足时才算完成：

- P0 和 P1 全部完成。
- P2 中 Agent 可靠性完成。
- S01-S20 场景测试全部通过。
- 所有性能目标通过。
- 页面、报告、导出、任务和 AI 栏 `scope_id` 一致率 100%。
- 每条正式结论可追溯到规则、指标和证据。
- 无 Mock、Placeholder、TODO 或虚假结论。
- 3-5 名真实运营用户可以进入 4 周试点。
