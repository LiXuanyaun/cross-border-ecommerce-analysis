# CrossBorder v3.1 Pilot Plan

制定日期：2026-07-21

## 目标

让 3-5 名真实跨境电商运营负责人连续 4 周完成“导入数据 -> 查看结论 -> 创建任务 -> 导出报告 -> 下周期复盘”，验证产品是否能稳定进入真实经营复盘。

## 参与用户

- 3-5 名跨境电商运营负责人。
- 每名用户至少有 2 个完整月订单数据。
- 用户可以提供商品、市场、客户、利润或退货字段中的至少 3 类核心字段。

## 4 周流程

| 周期 | 用户动作 | 产品记录 | 验收信号 |
| --- | --- | --- | --- |
| 第 1 周 | 导入 CSV/XLSX，确认字段、粒度、金额语义和数据质量 | 导入状态、阻断原因、能力矩阵、dataset_id | 导入成功率、阻断问题可修复率 |
| 第 2 周 | 查看 Overview 与五主题分析，核查证据和规则 | scope_id、rule_id、evidence_id、Drawer 打开记录 | 结论可信度、独立完成率 |
| 第 3 周 | 将异常、机会或洞察创建为任务并处理 | owner、deadline、status、result_note | 任务接受率、处理耗时 |
| 第 4 周 | 导出报告并复盘任务结果 | review_result、报告格式、导出耗时 | 复盘回访率、报告可用性 |

## 采集指标

- 导入成功率：成功生成 READY dataset_id 的导入次数 / 总导入次数。
- 复盘耗时：从打开 Overview 到导出报告的总耗时。
- 任务接受率：创建任务数 / 可执行建议数。
- 复盘回访率：已复盘任务数 / 已完成任务数。
- 结论可信度：用户能否根据页面证据复述结论口径。
- scope 一致率：页面、任务、报告和导出使用同一 scope_id 的比例。

## 规则校准

- 只记录真实任务结果，不改写历史异常事实。
- 每周整理误报、漏报、低样本和字段缺失案例。
- 阈值调整必须绑定用户证据、影响金额和规则版本。
- 缺少广告、库存、价格、活动等字段时，只记录为后续数据需求。

## 不进入试点

- 店铺 API 自动同步。
- 自动修改广告、库存、价格或店铺配置。
- 多租户权限。
- 自主规划或自动执行型 Agent。
