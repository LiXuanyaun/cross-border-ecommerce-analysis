# Project Context

## 1. Project Mission

项目为什么存在？

跨境电商团队拥有大量订单数据，但常常缺少统一口径、可信解释和可继续处理的经营结论。本项目要把原始交易数据转化为可追溯的经营判断，而不只是生成图表。

解决什么问题？

自动完成数据理解、经营指标计算、销售变化定位、商品组合分析、客户价值分群、区域比较和退货风险分析；结论必须带数据证据，证据不足时明确停止或跳过。

目标用户是谁？

需要进行周报、月报和经营复盘的跨境电商运营负责人，以及需要快速判断经营方向的管理者。当前形态面向本地单用户。

---

## 2. Product Goal

当前产品目标：

在 AutoClean 通用底座上，将 CrossBorder AI Analytics 从可演示 MVP 推进为可独立安装、可稳定验证、可处理完整业务明细的试用产品。

核心价值：

原始数据只读；指标口径透明；所有结论绑定证据；缺字段不猜测；用户能从汇总定位、筛选并导出需要处理的客户、商品或市场明细。

当前阶段：

2.0.0 本地 MVP。核心分析、中文 Dashboard、多格式报告和浏览器验收已经可用；独立依赖、CI、权限、SQL 和生产部署尚未完成。

## 4. Technical Architecture

技术栈：

Python、pandas、NumPy、Streamlit、Plotly、AgGrid、Matplotlib、openpyxl、python-docx、pytest、Streamlit AppTest 和 Playwright。

模块关系：

AutoClean 6.4 提供通用读取、字段契约、分析上下文、状态、模块执行器、证据、汇率和导出构建器。CrossBorder 项目提供电商字段契约、六类业务模块、RFM、建议规则、汉化、报告和 Streamlit UI。场景项目通过公共接口使用底座，不复制底层实现。

数据流：

只读原始文件 → `load_tabular` → `prepare_context` → `DatasetContext` 规范分析视图 → 汇率换算与筛选 → `PipelineRunner` 独立执行模块 → `AnalysisBundle` 汇总状态、证据和结果 → Dashboard、运营建议和多格式导出。

关键组件：

- `app.py`：单入口 Dashboard 和页面状态。
- `crossborder_analytics/service.py`：准备、汇率、筛选和流水线编排。
- `contract.py`：订单级字段契约和领域质量检查。
- `modules.py`：六个确定性分析模块。
- `rfm.py` 与 `recommendations.py`：客户分群和证据型建议规则。
- `localization.py` 与 `ui.py`：展示副本汉化、图表、表格和证据轨道。
- `reporting.py`：Excel、Markdown、DOCX 和 manifest 输出。
- `autoclean.analytics`：跨场景复用的非破坏性分析公共层。

## 5. Important Decisions

Decision: 原始业务数据始终只读，类型转换、字段标准化和币种换算只生成分析视图。

Reason: 商业分析必须可追溯，页面和报告不能悄悄改变源数据。

Date: 2026-07-16

Decision: 通用能力归 AutoClean，跨境项目只维护行业语义和业务规则。

Reason: 为未来库存、广告、物流和其他场景复用读取、契约、证据、状态和导出能力。

Date: 2026-07-16

Decision: 模块使用 `SUCCESS / SKIPPED / FAILED / FATAL`，核心字段或订单粒度冲突才停止全局分析。

Reason: 可选字段不足不应阻断仍有证据支持的其他分析。

Date: 2026-07-16

Decision: 统计模型与操作明细解耦，客户类型切换只影响客户清单，不改变 RFM 统计图和报告口径。

Reason: 用户需要处理具体对象，但页面操作不能隐式重定义分析模型。

Date: 2026-07-16

Decision: 暂不优先接入 LLM、SQL 和预测，先完成依赖、CI、字段映射和完整明细闭环。

Reason: 工程基础和证据边界未稳定时增加智能功能会放大安装、口径和可信度风险。

Date: 2026-07-16

## 6. AI Development Rules

修改代码时：

先读取当前仓库、契约、指标口径和测试；区分通用底座与场景模块；保持修改范围与用户实际业务动作一致。

必须：

- 使用中文沟通和中文 UI；缩写首次出现附中文解释，例如 `GMV（成交总额）`。
- 保持原始数据不变，汉化、搜索和格式化只能作用于展示副本。
- 每个结论和建议绑定证据 ID、公式、字段、周期与样本；证据不足时明确跳过。
- 对“调节、筛选、切换、自定义”先确认操作对象、动作和影响范围。
- 同时验收汇总、解释和可操作明细，检查 `.head()` 或抽样是否静默隐藏数据。
- 前端点击、层级和响应式问题先用真实浏览器复现并读取 DOM，再做最小修改。

不要：

- 不要自动去重、填充核心字段、删除异常业务事实或覆盖用户文件。
- 不要把贡献或关联写成未经数据支持的因果关系。
- 不要因单个可选模块缺字段而让全部分析失败。
- 不要让 UI 筛选改变固定统计模型、报告或导出口径。
- 不要在依赖、CI、安全和明细闭环之前优先堆叠 LLM 或装饰性图表。

测试要求：

- 单元测试覆盖指标公式、零分母、缺字段、重复订单、低样本、汇率和 DataFrame 不可变性。
- Streamlit AppTest 覆盖组件状态和筛选影响范围。
- Chrome/Edge Playwright 覆盖真实点击、侧栏、表格、搜索、下载和窄屏布局。
- 修改共享底座或计算口径时同时运行 AutoClean 与 CrossBorder 回归测试。

文档要求：

- 指标语义、字段契约、状态边界和已知限制必须与代码同步。
- 稳定架构与决策写入本文件；每日变化写入 `docs/founder-log/`。
- 发布时更新 README、CHANGELOG、测试结果和迁移说明，避免只记录实现细节。

## 7. Known Risks

当前风险：

AutoClean 6.4 仍在 Draft PR；跨境项目通过 `-e ../AutoClean-v1` 依赖相邻目录，独立克隆和 CI 尚不能可靠安装。

技术风险：

pandas + Streamlit 尚未验证百万级订单；商品页面只展示前500项；可选字段映射、结构化日志、依赖锁定、Linux 验证、报告视觉回归和在线汇率稳定性仍不足。

产品风险：

当前假设一行一订单，不支持订单明细、多店铺和实时接入；没有成本、退款、库存、广告或物流节点时，不能计算真实净利润、退款损失或完整归因。

商业风险：

真实团队的持续使用意愿、建议带来的量化收益、目标客户付费意愿和数据接入成本仍未知。当前只有样例与开发验收，尚未形成真实用户验证闭环。
