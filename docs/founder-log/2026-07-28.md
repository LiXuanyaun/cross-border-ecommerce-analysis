# 2. 今日项目推进

## 产品能力变化

昨天：订单分析、任务、报告和受控 Agent 已形成试点级主链路，但广告、退款和物流尚未进入统一事实层，架构职责也需要继续收敛。

今天：完成 AdventureWorks 订单适配，以及广告、归因、退款、物流和轨迹的独立事实模型；Dashboard、专题分析、报告、manifest 和受控 Agent 复用同一批注册指标、异常规则、证据和限制。同时拆分 FastAPI 路由、服务、Presenter、Agent 上下文和前端 feature 模块，并保持既有 API 契约。

现在：v4.0.0 已打标签。产品可以从多业务文件导入一路追溯到经营结论、行动建议、任务和报告；模拟扩展数据会在 API、页面、报告和 Agent 上下文中持续披露。

---

## 用户价值变化

运营人员不再需要分别核对订单、投放、退款和物流表。系统能在同一数据范围内定位德国搜索广告、Clothing 尺码退货和 GlobalPost 欧洲线路延误等对象，并展示指标、阈值、证据、限制和建议动作；数据不足或仅为模拟场景时不会伪装成真实经营事实。

---

# 3. 今日关键决策

Decision: v4.0.0 发布后暂停继续扩展功能广度，优先用真实广告、退款、物流数据和 3-5 名试点用户验证规则、任务采纳与持续使用。

Reason: 当前工程闭环已经跨越订单、广告、退款和物流，但新增三类数据仍是模拟扩展数据；继续增加成本、库存或更多 Agent 自主性，不能替代真实经营数据与用户行为证据。

Alternatives: 立即继续接入成本、库存、活动、渠道和店铺，或直接扩大 Agent 的自主规划与执行范围。

Impact: 下一阶段的成功标准从“功能是否存在”转为“真实数据能否稳定接入、结论是否被信任、建议是否进入行动并产生可复盘结果”。

# 4. 当前项目状态

## 产品

当前能力：React + FastAPI 主产品已覆盖导入、数据质量、订单与多业务分析、证据、建议、任务、报告和受控 Agent；Streamlit 仅用于兼容与口径对照。

下一阶段：完成真实数据复验和小规模用户试点，再依据证据决定是否扩展成本、库存、多店铺连接器与 Agent 能力。

## 技术

当前状态：本轮复核后端 114 项通过、6 项跳过；前端 4 项通过，生产构建成功。发布记录中的桌面/393px 浏览器验收和 100,000 行 SQLite 基准已通过，基准为 10.069 秒；本轮未重跑浏览器验收与性能基准。

技术风险：FastAPI 测试出现 Starlette TestClient/httpx 弃用警告；SQLite 快照与缓存容量仍会随数据集增长；双前端链路仍需防止口径回归；模拟数据阈值不能直接迁移为真实业务阈值。

## 商业

已经验证：系统可以在多业务粒度下保持数据血缘、统一指标、证据链和显式降级，且发布门槛可重复通过。

未知问题：尚无真实试点证明持续使用、建议采纳、节省时间、经营收益、接入成本或付费意愿；当前版本不能被称为已验证商业产品。

---

# 5. 今日最大阻碍

问题：广告、退款和物流扩展数据仍是模拟数据，缺少真实商家数据与用户使用反馈。

影响：现有结果只能证明产品和规则链可运行，不能证明异常阈值适合真实业务，也不能证明建议会被采用或产生收益。

已经尝试：对模拟来源持续披露，以独立事实表、导入批次、文件哈希、业务键、外键、注册规则和证据记录保证场景可审计，并完成全套发布验收。

下一步：选择一个真实商家数据集，完成字段映射、质量降级、阈值复验和一次从异常到任务复盘的端到端观察。
