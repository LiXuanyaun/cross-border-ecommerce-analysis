## 0. 执行摘要

本次交付面向跨境电商运营负责人、经营分析人员和管理者，集中修复当前产品从启动、选数、导入、专题分析到 AI 解读的核心使用链路。交付必须同时解决专题证据点击崩溃、AI 分析师停摆、多业务专题颗粒度不足、页面加载缓慢、数据来源不透明、导入流程不清和单批 20 文件限制，并正式移除已停止承担主产品职责的 Streamlit 双 UI 链路。

本次不是新增一套分析体系。AutoClean 6.6 继续作为非破坏性加载、字段契约、质量校验和存储底座；SQL 与注册指标继续作为正式事实层；React + FastAPI 是唯一主产品。AI 只读取与页面同源的正式分析结果并改善表达，模型不可用时仍须返回确定性分析。

## 1. 核心定义

### 1.1 一句话定义

CrossBorder AI Analytics 是一个基于 AutoClean 的跨境电商经营分析产品，通过可追溯的数据导入、统一专题分析和受控 AI 解读，帮助运营人员快速确认正在使用的数据、发现经营问题并获得有证据的行动建议。

### 1.2 本次产品定位

本次负责：

- 修复专题分析证据卡片点击后的页面崩溃。
- 恢复 AI 分析师的确定性分析、模型增强、降级与 Markdown 展示链路。
- 使广告、退款、物流多业务专题与现有专题分析达到相同颗粒度。
- 定位并处理主要数据调用与页面展开性能瓶颈。
- 建立全局当前数据集选择和持续可见的数据来源说明。
- 将现有 AutoClean 能力组织成清晰、可恢复的导入流程。
- 取消固定 20 文件限制，改为可配置的资源限制和自动分批处理。
- 提供根目录一键启动方式，并删除 Streamlit 兼容链路。

本次不负责：

- 新增成本、库存、活动、店铺或渠道事实域。
- 新建预测模型、自动投放或自动运营功能。
- 将模拟扩展数据包装为真实经营数据。
- 开放任意 SQL、让 Agent 修改业务数据库或自动执行任务。
- 超出现有专题分析颗粒度扩展多业务专题。
- 云部署、多租户、权限系统或移动端 App。

### 1.3 设计原则

1. 数据身份先于分析：未明确选择数据集时不得产生经营结论。
2. AutoClean 是导入和质量底座，项目代码只补充业务适配与业务规则。
3. SQL 和注册指标是事实层，页面与 AI 不得自行计算不同口径。
4. AI 负责解释，不负责发明事实。
5. 任何缺失、弱质量、模拟来源或不完整周期都必须显式降级。
6. 一日交付以完整闭环和自动验证为准，不以隐藏缺陷换取表面完成。

## 2. 商业目标

### 2.1 用户与商业问题

| 问题 | 用户影响 | 产品影响 |
|---|---|---|
| 点击专题证据后页面报错 | 无法复核结论 | 证据型分析的核心承诺失效 |

- 不以新增分析结论数量作为成功指标，避免为填充页面制造弱证据结论。

## 3. 用户场景

### 3.1 主要用户

**主要角色：** 跨境电商运营负责人或经营分析人员。  
**工作环境：** Windows 本地工作区，数据通常来自 CSV、Excel 或业务系统导出目录。  
**核心目标：** 快速确认数据范围，完成经营复盘，复核异常证据并获得可执行建议。  
**当前痛点：** 启动、选数、导入和分析之间缺少清晰连续的工作流。

### 3.2 典型场景

| 场景 | 时间 | 用户任务 | 期望结果 |
|---|---|---|---|
| 首次使用 | 获取项目后 | 启动产品并决定使用示例或自己的数据 | 一次操作打开主产品，不误用示例数据 |
| 数据接入 | 周期复盘前 | 导入多个文件或一个业务目录 | 看懂预检、映射、质量、进度和最终数据身份 |
| 专题复盘 | 每周或每月 | 在专题中查看指标、异常和证据 | 点击任何证据都能看到可理解的计算依据 |
| 多业务复盘 | 广告、退款或履约复盘 | 使用与普通专题一致的分析深度 | 不需要重新学习另一套粗糙页面 |
| AI 解读 | 发现异常后 | 让 AI 解释已存在的分析结果 | 得到不篡改事实、可追溯的 Markdown 回答 |

### 3.3 Jobs-to-be-Done

- 功能任务：从原始业务文件得到同一范围内可复算的分析、证据和解释。
- 情绪任务：确信当前看到的不是另一份数据、旧缓存或伪造结论。
- 协作任务：将同口径结果导出或交给管理者复核。

## 4. 输入数据

### 4.1 支持来源

- CSV 文件。
- XLSX 文件及指定 Sheet。
- 多文件批次。
- AdventureWorks 及多业务目录适配输入。
- 内置示例数据，仅在用户明确选择后使用。

### 4.2 AutoClean 职责

- `load_tabular` 负责通用表格读取。
- `prepare_context`、`DatasetContract`、`FieldSpec` 和 `ValidationIssue` 负责字段识别、映射和问题契约。
- `assess_data_quality` 负责正式数据质量评估。
- AutoClean SQLite 表负责数据集、问题、查询运行和血缘记录。
- AdventureWorks 与多业务适配器只转换源结构，不重复实现 AutoClean 已提供的通用能力。

### 4.3 最低订单字段

| 标准字段 | 类型 | 用途 | 缺失行为 |
|---|---|---|---|
| `order_id` | string | 订单身份与去重 | 阻断导入 |
| `order_date` | date | 周期分析 | 阻断导入 |
| `total_amount` 或正式金额字段 | number | GMV 与客单价 | 阻断导入 |
| `currency` 或明确批次币种 | string | 金额口径 | 无法确认时阻断金额结论 |
| `product_id`、`customer_id`、市场字段 | string | 对应专题分析 | 缺失时对专题显式降级 |
| 成本、退款、物流字段 | domain-specific | 利润、退款、物流专题 | 缺失时禁止伪造相关结论 |

完整字段字典继续以现有正式数据字典与 AutoClean 契约为准，PRD 不复制全部字段清单。

### 4.4 容量规则

- 取消固定“单次最多 20 个文件”限制。
- 默认单文件上限 100MB。
- 默认单次导入任务总量上限 1GB。
- 上限必须集中配置，不得散落在前后端硬编码。
- 文件较多时服务端自动分批预检与处理，对用户仍表现为一个导入任务。
- 导入实现不得一次将整个 1GB 批次全部保留在内存。

## 5. 核心功能

### 5.1 专题证据可靠性

**目标：** 用户可从任一专题证据卡片安全进入证据详情。

**现状根因：** 前端 `TopicEvidence` 期望 `id/metric/value/claim/sample_size/confidence/source_fields`，后端实际传递正式 `EvidenceBundle` 的 `evidence_id/query_name/row_count/result_summary/limitations` 等字段，点击后访问不存在的 `sample_size` 并导致渲染错误。

**要求：**

- 后端 Presenter 提供单一、版本化、面向用户的专题证据契约。
- 前端生成类型必须与 OpenAPI 契约一致，不维护另一套手写假结构。
- 证据抽屉展示结论、指标和值、周期与筛选、公式、样本量、来源字段、数据质量和限制。
- 默认隐藏查询名、UUID、数据库版本和摘要哈希等内部信息。
- 任一可选字段缺失时展示“数据不可用”，不得导致页面崩溃。

### 5.2 AI 分析师恢复与同源分析

**目标：** AI 分析师在模型可用或不可用时都能完成分析。

**流程：**

1. 根据当前 `dataset_id`、`scope_id`、周期和筛选读取正式分析结果。
2. 根据问题只选择相关的注册工具和专题，不默认重跑全部多业务专题。
3. 先生成确定性答案。
4. 模型可用时仅基于受控工具结果改善结构与表达。
5. 校验模型输出中的关键数字、币种、周期、来源和证据引用。
6. 模型失败或校验失败时返回确定性答案并显示降级状态。

**多业务要求：** 广告、退款、物流必须使用各自正式分析结果进入同一 Agent 工具链，不建立另一套 AI 计算逻辑。

### 5.3 AI Markdown 输出

- 后端返回原始受控 Markdown，不拼接 HTML。
- 前端使用成熟 Markdown 解析与清理库。
- 支持标题、段落、列表、表格、引用、粗体和安全链接。
- 禁止执行原始 HTML、脚本、事件属性和危险协议链接。
- Markdown 解析失败时回退纯文本。
- 数据范围、来源、质量和限制以固定区块补齐，模型不可省略。

### 5.4 多业务专题对齐

**目标：** 广告、退款、物流的页面颗粒度和交互能力与当前普通专题分析对齐。

**对齐基准：** 普通专题当前已存在的摘要、核心指标、周期比较、趋势、构成、排名、异常/驱动/证据/建议区域、明细筛选分页和详情交互。

**边界：** 只做对齐，不额外增加普通专题尚不存在的高级报告、任务或 AI 功能。

### 5.5 全局数据集与来源

- 顶部全局区域持续显示当前数据集名称并允许切换。
- 来源详情至少包含：名称、`dataset_id`、来源文件或适配器、导入时间、数据期间、真实/示例/模拟状态和质量状态。
- 用户选择在本地持久化；页面、报告和 AI 继承同一选择。
- 新导入成功后询问是否切换，不静默切换。
- 当前数据集失效时阻断分析并要求重新选择。
- 禁止 API 和前端静默回退到 `demo-all`。

**首次启动：**

- 无历史选择时显示“使用示例数据体验”和“导入我的数据”。
- 只有用户主动选择后才加载示例数据。
- 未选择数据集时，各分析页显示可行动的空状态。

### 5.6 AutoClean 导入向导

1. **选择来源：** 文件、多文件或目录。
2. **AutoClean 扫描预检：** 识别格式、业务类型、文件数、行数、重复、字段和容量风险。
3. **字段映射：** 自动匹配正式契约，仅要求用户处理低置信度或无法确认字段。
4. **质量校验：** 显示必填缺失、币种、日期、粒度、关联率、来源真实性和质量等级。
5. **确认导入：** 说明将创建或复用的数据集、原子性和失败影响。
6. **处理与完成：** 显示总数、进度、成功、跳过、失败、血缘和下一步。

**恢复能力：** 问题文件修复后可重试失败分片；同源同契约重复导入复用原 `dataset_id`；正式业务行仍以整批原子提交为边界。

### 5.7 性能优化

已识别的主要原因：

- 首次请求才通过 AutoClean 加载和准备示例数据，导致首个分析请求承担冷启动成本。
- 新数据范围会生成完整分析包并复制 pandas DataFrame；专题基础结果虽有内存缓存，但每个新范围仍成本较高。
- 多业务分析没有等价结果缓存，每次请求重新连接 SQLite 并读入 pandas。
- AI 上下文每次构建普通分析，并对符合条件的数据集重跑广告、退款、物流三个专题。
- 导入预检与正式提交重复上传、重复读取文件，且当前逐文件完整读入内存。
- 页面文件体积较大，非关键模块和图表初始化仍可能阻塞主要内容呈现。

优化要求：

- 建立以 `dataset_id + scope_id + topic + 数据版本` 为键的服务端结果缓存。
- 导入、归档或数据版本变化后精确失效相关缓存。
- AI 复用同范围正式结果，只按问题加载相关专题。
- 将首屏关键数据与非关键详情拆分，允许骨架和渐进展示。
- 避免为分页请求生成和保留不必要的全量公开记录。
- 导入预检生成短期任务或暂存引用，提交阶段不得要求浏览器重新上传同一批文件。
- 记录 API、SQL、分析、序列化和前端渲染各阶段耗时。

### 5.8 一键启动与旧链路移除

- 根目录新增 `start.cmd`，支持双击和命令行启动。
- 默认启动 `private` 模式。
- 检查 Python、Node、依赖、构建产物和端口占用。
- 仅在依赖缺失或前端源文件发生变化时安装/构建。
- 后端健康检查成功后自动打开主产品页面。
- 错误信息必须指出失败阶段和可执行修复建议。
- 删除 `app.py`、`crossborder_analytics/ui.py`、`crossborder_analytics/phase2_ui.py`、Streamlit 专属测试和 Streamlit 专属依赖。
- 浏览器调试工具默认地址改为 React 主产品的 8000 端口。
- 历史日志、审计和 CHANGELOG 保留历史事实，不追溯改写。

## 6. 业务规则

| 条件 | 系统行为 |
|---|---|
| 未选择数据集 | 阻断分析，提供示例或导入入口 |
| 数据集不存在或已归档 | 清除失效选择并要求重新选择 |
| 数据来源为示例或模拟 | 页面、报告和 AI 持续显示来源标识 |
| 字段或质量不足 | 对受影响指标、专题和 AI 结论显式降级 |
| 周期不完整或不可比较 | 禁止输出确定性环比结论 |
| 模型未配置或调用失败 | 返回确定性分析，状态为降级而非整次失败 |
| 模型输出改变正式数字或证据 | 丢弃模型输出，返回确定性答案 |
| 证据字段缺失 | 显示不可用字段与限制，不抛出页面异常 |
| 重复来源、版本和契约 | 复用原 `dataset_id`，不增加业务行 |
| 任一正式导入分片出现致命错误 | 不提交该原子批次的业务行 |
| 文件较多 | 自动分批处理，不因文件数本身拒绝 |
| 单文件或任务总量超过资源上限 | 预检阶段阻断并显示实际值、上限和解决方式 |

## 8. AI 行为边界

### 8.1 状态

- `SUCCESS`：正式结果与可选模型增强均通过。
- `PARTIAL`：正式结果成功，但模型失败或增强结果未通过校验，已返回确定性答案。
- `SKIPPED`：数据或证据不足，返回明确限制而不强行回答。
- `FAILED`：单次可恢复执行失败。
- `FATAL`：数据身份、正式事实层或运行环境不可用，无法继续。

### 8.2 允许

- 查询注册工具和参数化分析服务。
- 读取当前范围的正式指标、异常、诊断、建议和证据。
- 根据已有结果组织 Markdown 回答。
- 生成可复核的任务草稿或报告摘要，但仅限现有能力。

### 8.3 禁止

- 修改、删除或覆盖用户业务数据。
- 执行任意 SQL。
- 跨 `dataset_id` 或 `scope_id` 混合数据。
- 自行重算不同于正式指标的数字。
- 将贡献、相关性或时序关系表述为已证明因果。
- 将退货关联 GMV 表述为退款损失。
- 隐藏模拟来源、质量不足、字段缺失或不完整周期。
- 用模型生成内容覆盖通过校验的确定性事实。

## 9. 交互设计

### 9.1 全局状态

- 当前数据集和来源状态在所有主页面可见。
- 页面跳转保留 `dataset_id`、周期和仍适用的筛选条件。
- URL、页面标题、指标和详情必须保持一致。

### 9.2 加载状态

- 首屏先展示页面骨架和已知数据范围，不等待非关键详情。
- 超过 1 秒的操作显示当前阶段和进度。
- 超过 5 秒的分析自动记录慢阶段，但不中断用户流程。
- 不使用整页白屏或无期限“处理中”。

### 9.3 证据交互

- 点击证据在当前页面打开抽屉或等价详情面板。
- 抽屉关闭后保留原筛选、滚动位置和卡片状态。
- 证据不可用时展示限制，不跳转到错误页。

### 9.4 AI 交互

- 1 秒内展示运行已开始及当前阶段。
- 分析进行中显示受控工具阶段，不暴露内部 UUID 或查询名。
- 回答区按安全 Markdown 展示。
- 降级状态解释模型失败，但不把技术异常堆栈展示给用户。

### 9.5 导入交互

- 每一步说明当前决定、问题和下一步动作。
- 进度以文件数、行数和处理阶段共同呈现。
- 失败项可定位到文件和原因。
- 导入完成后由用户决定是否切换到新数据集。

## 10. 技术约束

### 10.1 支持

- Python 3.10+、AutoClean 6.6、pandas、SQLite、FastAPI。
- React 18、TypeScript、TanStack Query、ECharts。
- Windows 本地启动；React + FastAPI 单一主产品。
- CSV、XLSX、AdventureWorks 与现有多业务适配格式。
- 默认单文件 100MB、单任务 1GB，可通过集中配置调整。

### 10.2 性能门槛

在 10 万行代表性数据、开发机本地运行条件下：

- 应用就绪后首个页面可见内容不超过 2 秒。
- 普通专题和多业务专题冷打开不超过 3 秒。
- 已加载数据下专题切换不超过 1 秒。
- 筛选、分页和详情展开不超过 1 秒。
- AI 在 1 秒内显示执行状态，确定性分析不超过 10 秒。
- 外部模型耗时单独展示，不计入确定性分析计算时间。

测试必须记录机器环境、数据集、冷/热缓存状态和 P50/P95；不得只报告单次最佳值。

### 10.3 不支持

- 宣称真正无限文件或无限数据容量。
- 实时数据库同步、分布式任务系统或云对象存储。
- Streamlit 兼容界面。
- 未注册指标和任意 SQL。

## 11. 异常处理

| 异常 | 用户提示 | 系统行为 | 可恢复方式 |
|---|---|---|---|
| 证据契约字段缺失 | 部分证据信息不可用 | 渲染已有字段并记录契约错误 | 修复契约后刷新 |
| 数据集失效 | 当前数据集不可用 | 阻断分析，不回退示例 | 重新选择数据集 |
| API 超时 | 分析超过预期时间 | 保留页面、记录慢阶段 | 重试或缩小范围 |
| 模型不可用 | 已使用确定性分析 | 返回 `PARTIAL` | 修复模型配置后重试 |
| Markdown 非法 | 回答以纯文本显示 | 清理危险内容 | 无需用户处理 |
| 导入格式不支持 | 指明文件和支持格式 | 预检阻断，不写业务数据 | 转换格式后重试 |
| 映射置信度低 | 要求确认字段 | 暂停正式导入 | 用户确认或修改映射 |
| 批次容量超限 | 显示实际值和配置上限 | 不进入内存处理 | 拆分任务或调整配置 |
| 分片失败 | 显示失败文件和原因 | 不提交原子批次 | 修复后从失败项重试 |
| 端口占用 | 显示占用端口和进程信息 | 不覆盖其他服务 | 选择空闲端口或关闭占用 |
| 依赖缺失 | 指明缺失项和安装命令 | 停止在对应阶段 | 补齐依赖后重启 |

## 13. 当日开发阶段规划

当日交付不减少问题项，只通过并行工作流和严格闸门控制时间。任何未通过验收的项目不得标记完成。

### 阶段 A：基线与契约冻结

- 记录核心 API、页面和 AI 当前耗时。
- 固化专题证据、数据集来源、AI 结果和导入任务契约。
- 建立八项问题的失败回归测试。

**完成闸门：** 每个已报告问题至少有一个可重复失败的验证。

### 阶段 B：阻断问题修复

- 修复证据契约与详情容错。
- 修复 AI 会话/SSE/降级链路和 Markdown 渲染。
- 建立全局数据集选择、来源展示与首次启动状态。

**完成闸门：** 专题证据、AI 和数据身份三条核心路径端到端通过。

### 阶段 C：数据接入与性能

- 将导入流程收敛为 AutoClean 驱动的任务式向导。
- 替换固定文件数限制，增加集中容量配置、自动分批、暂存引用、进度和重试。
- 优化普通专题、多业务专题和 AI 的查询复用、缓存与渐进加载。

**完成闸门：** 10 万行性能达标；超过 20 文件的测试批次可完成；重复导入保持幂等。

### 阶段 D：多业务对齐与启动收口

- 按普通专题现有颗粒度补齐广告、退款、物流。
- 新增 `start.cmd` 并验证全新终端启动。
- 删除 Streamlit 链路及专属依赖，更新当前文档和测试。

**完成闸门：** 三个多业务专题完成对照验收；主产品可一键启动；仓库无运行时 Streamlit 引用。

### 阶段 E：总体验收

- 运行后端、前端、构建、浏览器和性能验证。
- 检查数据身份、来源和模拟状态跨页面一致。
- 记录未通过项；未通过项必须当日修复，不转为未说明的后续工作。

## 14. 依赖、风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 一日范围跨前后端、数据和启动链路 | 时间压力导致测试不足 | 先建立失败测试，按完成闸门串联交付，禁止范围外重构 |

| 模拟与真实数据混淆 | 错误经营判断 | 后端契约携带来源状态，所有消费者必须显示 |

## 16. PRD 自评

**最强部分：** 问题范围、禁止边界和验收标准。它们来自用户逐项确认以及当前代码契约、调用链和依赖扫描。

**最弱部分：** 性能目标与 1GB 容量的当前基线尚未实测，因此目标是否需要针对机器环境校准仍存在不确定性。

**最高风险假设：**

| 假设 | 风险 | 验证方式 |
|---|---|---|
| 主要慢点来自重复分析、无缓存多业务查询和重复导入读取 | 优化后仍无法达标 | 分阶段计时与调用次数追踪 |
| AutoClean 可在项目层任务编排下安全支持大批次 | 导入架构需要上游改造 | 代表性 1GB 或等比例压力测试 |
| 一日内可以完成全部跨层变更 | 验证被压缩或出现回归 | 以自动化闸门决定完成，不以时间宣告完成 |

**推荐下一步：** 按阶段 A 先建立失败回归和性能基线，再开始代码修改；不得先做视觉调整或无关重构。
